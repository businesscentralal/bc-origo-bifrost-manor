# Changelog

All notable changes to Bifrost Manor are documented here.

## [28.0.0.0] - 2026-11-27

### Added
- [Story H (#8)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/8): contract-replay suite `Manor Contract Tst ori` (98280) with runner codeunit 98281: every one of the 24 Manor message types replays a Mock happy path and 401/403/404/422/503 error mapping in 1033 and 1039, a catalogue guard fails when a new `Manor.*` type has no case, and the no-delete guard asserts no `*.Delete` type and no HTTP DELETE. Added `docs/manual-verification.md` for the manual test-instance run (no instance name or key). Test app only; no product objects.
- Manor.TimeEntry.Create, Manor.Expense.Create and Manor.Product.Create with expectedCount=1, dryRun previews, bilingual contracts, mock tests, time validation and default expense VAT. Objects: codeunits 10035650, 10035677, 10035683–10035684; enum extension 10035683; test codeunit 98270.
- Create-specific client overload sends once and returns safe localised errors without provider text.
- [Story (#6)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/6): six write message types `Manor.Client.Create/Update`, `Manor.Project.Create/Update` and `Manor.Activity.Create/Update` with `expectedCount` confirmation (refused before any call on a mismatch), per-record 400/422 errors, duplicate-kennitala refusal on client create, `confirmCurrencyChange` for currency changes, billing values enabled/internal/sensitive, project close and reopen, and the `manage_activities` permission hint. New objects: codeunits 10035671-10035676 (Impl), 10035678 (Manor Write Handler ori), 10035679 (Manor Contract Parts ori); enum extension 10035677 (`Manor Write Msg Type ori`, renamed during the main merge to avoid a name collision with read enum extension 10035655; IDs and message names unchanged); test codeunit 98260.
- [Read message types (#3)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/3): `Manor.Connection.Test`, `Manor.Firm.List`, `Manor.User.List`, `Manor.User.Get` and `Manor.Rate.List`, with bilingual discovery/contracts (including explicit Icelandic metadata in canonical English catalogue contracts), canonical response fields and paging. Optional user permission filters go to Manor; enabled-user and rate-type filters run in Business Central. The connection test records a successful timestamp without granting setup editing to the read role. New objects: enum extension 10035655; codeunits 10035656–10035660; bilingual test codeunit 98230 and test-only mock probe objects 98231–98232. Rate-list 403 errors always name `manage_rates`; message reads do not echo upstream 422 details. Existing client Get/Post/Put contracts are preserved. The Read role can use the stored key only for GET requests and still cannot edit setup or keys or send writes. Email lookup safely escapes a single user path segment; encoded delimiters, control characters and double encoding are rejected.
- [Read message types (#5)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/5): `Manor.TimeEntry.List`, `Manor.Product.List`, `Manor.Invoice.List`, `Manor.Invoice.Get` and `Manor.InboundInvoice.List`, with EN/is-IS discovery and explicit bilingual contract descriptions (including through Foundation's English contract boundary), canonical JSON, bounded complete pagination, read-role permissions and localized errors. Time uses one day; updated inbound invoices de-duplicate by id before optional validated local status filtering. Invoice contracts identify the upstream Beta status. New objects: enum extension 10035666; implementation codeunits 10035666–10035670; bilingual test codeunit 98250, mock fixture table 98251 and subscriber codeunit 98252 (test app only).
- [Story D (#4)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/4): read message types `Manor.Client.List`, `Manor.Client.Get`, `Manor.Project.List` (open projects by default, Gunnar 26.11.2026), `Manor.Project.Get` and `Manor.Activity.List`, each with an EN + is-IS contract, mapped Manor errors (401/403 with the `manage_activities` hint, 404, 422) and no secrets in any answer. New objects: enum extension 10035680; codeunits 10035661-10035665 (Impl), 10035681 (contract parts), 10035682 (shared reading and response mapping); test codeunit 98240. The client, query builder, transport and telemetry codeunits moved into `BIFROST MnrRead ori` so a read-only user can run the types.
- [Story B (#2)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/2): Manor API client (`Manor Client ori`: Get, GetAll with paging, Post, Put; no delete) with one retry on 429/5xx, documented EN/IS error mapping that never echoes the key, query or body, an ISO 8601 query builder and path-template telemetry. The mock store gained queued per-query responses. New objects: codeunits 10035651–10035654; bilingual test codeunit 98220.
- [Story A (#1)](https://github.com/businesscentralal/bc-origo-bifrost-manor/issues/1): Manor Setup with disabled Mock defaults, validated instance identifiers, a masked API-key dialog, company-scoped SecretText storage, and restrictive Full/Read permissions. Clear and setup deletion remove the key.
- Production/Test transport on a fixed host and a session-local mock with registered responses and request capture. New objects: table 10035641; pages 10035642, 10035647; enum 10035643; interface Manor Transport ori; codeunits 10035644–10035646, 10035648–10035649; bilingual test codeunit 98202. Foundation registration now opens Manor Setup.
- Repository scaffold: app registration with Bifröst Foundation, Bifrost Manor permission sets wired into the Foundation Full and Read roles, AL-Go CI/CD and source guards.
- Manor API reference summary (`docs/manor-api-summary.md`).

### Fixed
- Resolve object-ID collisions with the merged write types: move Manor Expense Create Impl ori to codeunit 10035683, Manor Product Create Impl ori to codeunit 10035684, and Manor Message Types ori to enum extension 10035683. Existing enum value IDs, message names and contracts are unchanged.
